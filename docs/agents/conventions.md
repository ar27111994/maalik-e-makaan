# Conventions

The rules every change follows, with where each is enforced. `CONTRIBUTING.md` is the short
human version; `.planning/PROJECT.md` (<!-- docs:decision-range from .planning/PROJECT.md decisions; generated by make docs, do not edit -->D-01 to D-20<!-- /docs:decision-range -->) records why.

## Commits and pull requests

- Conventional Commits, checked by commitlint (`commitlint.config.mjs`) in the `commit-msg` hook
  and in CI. Allowed scopes: <!-- docs:commit-scopes from commitlint.config.mjs scope-enum; generated by make docs, do not edit -->`app`, `core`, `ui`, `db`, `functions`, `web`, `ci`, `deps`,
  `deps-dev`, `docs`, `formal`, `planning`, `release`, `repo`, `security`, `test`<!-- /docs:commit-scopes -->. A scope
  outside the list fails (`feat(foo): …` is refused).
- Body lines at most <!-- docs:commit-body-max from commitlint.config.mjs body-max-line-length; generated by make docs, do not edit -->100<!-- /docs:commit-body-max --> characters; the subject is not <!-- docs:commit-subject-case from commitlint.config.mjs subject-case; generated by make docs, do not edit -->upper, Pascal or Start<!-- /docs:commit-subject-case --> case
  (sentence case is allowed: some of Dependabot's commits read `chore(deps): Bump …`).
- Pull requests are squash-merged; `pr-title.yml` checks the title's type and scope against the
  same lists, and is stricter about the subject, which must start with a lower-case letter. It
  also checks that the title with the `(#123)` GitHub adds when it squash-merges stays within
  commitlint's <!-- docs:commit-header-max from commitlint.config.mjs header-max-length; generated by make docs, do not edit -->100<!-- /docs:commit-header-max -->-character header.
- release-please writes `CHANGELOG.md` and the version from these messages
  (`release-please-config.json`), so the type matters: <!-- docs:changelog-visible from release-please-config.json changelog-sections; generated by make docs, do not edit -->`feat`, `fix`, `perf`, `revert` and `docs`<!-- /docs:changelog-visible -->
  appear in the changelog, and <!-- docs:changelog-hidden from release-please-config.json changelog-sections; generated by make docs, do not edit -->`build`, `chore`, `ci`, `refactor`, `style` and `test`<!-- /docs:changelog-hidden --> do not,
  unless the commit is breaking (`!`) or has a `Release-As:` footer. Each section needs a heading in both languages on
  the website's release notes page (`website/src/i18n/ui.ts`, `releases.sections`).

## Language and text

- British English in prose, comments and UI text: licence, colour, organisation, catalogue.
- Every string a person sees is in English and Urdu. App strings live in
  `app/lib/l10n/arb/app_en.arb` (the template) and `app_ur.arb`; every key needs its `@key`
  description (`required-resource-attributes: true` in `app/l10n.yaml`). Website pages exist
  in both languages or the build fails.
- Screens work right to left: directional geometry only (`EdgeInsetsDirectional`,
  `AlignmentDirectional`); the design lint refuses `left`/`right`.
- Plain Urdu: the everyday Urdu an ordinary landlord or tenant reads easily on a phone. Where
  people say an English word, write it in Urdu script (the security deposit is `سیکیورٹی`, a late
  fee `لیٹ فیس`). Short sentences, active voice, common verbs; amounts, dates, deadlines, warnings
  and legal effect say exactly what the English says. The owner's glossary,
  [`contracts/urdu_glossary.json`](../../contracts/urdu_glossary.json), gives each formal word to
  avoid with the word to write instead (`prefer`), the English and a note, then the sentence rules
  (`sentenceRules`) and the words that stay (`keep`). `tool/check_urdu_words.py` (`make lint`, the
  pre-commit hook) fails when a tracked file has one of an entry's `match` forms as a whole word,
  also with an izafat zer or hamza after it, and also when it is typed with the Arabic keyboard's
  yeh, kaf or heh, so a `match` list needs neither the izafat form nor the Arabic spellings.
  An entry with an empty `match` depends on meaning (`مکان` is right for a home, not for a shop)
  and is judged in review. An official name, a quoted law or a table of letters that must keep a
  formal word goes in the glossary's `exceptions` as `path` (a glob), `avoid` (the form, or a
  longer phrase containing it, which then allows the form only inside that phrase) and `reason`.
- Unicode guard: `tool/check_unicode.py` fails on bidi overrides and isolates, zero-width and
  other invisible characters, and C0/C1 controls in any tracked file; the contract is
  `contracts/clean_text.json`. Urdu's ZWNJ/ZWJ and LRM/RLM are allowed. Code that needs a
  forbidden character builds it from its code point.

## Money, time and identity

- Money is whole paisa in integers: `Money` in `mm_core`, `numeric(14,2)` in SQL, decoded with
  `Money.fromJson`. Never `double`. Percentages are basis points in Dart, `numeric(5,2)` in SQL.
- Financial rows are never deleted, only voided with a reason; a voided row cannot change.
- Payments are written only through `record_payment`, with an idempotency key the form creates
  once and reuses for every retry.
- Dates without a time are `CalendarDate`; "today" is Pakistan time. The tax year runs 1 July to
  30 June.
- A person's own time zone is only for their alerts, digests, quiet hours and the second time of
  a dual time (`Residence.alertZone`, `QuietHours`, `DualTime`); ledger and due dates, deadlines,
  the tax year and messages to tenants stay on Pakistan time ([time](../architecture/time.md)).
  Residence is declared by the person, never inferred (not from a +92 number, the store, an IP
  address, the app's language or a currency), and never answers a portfolio's owner-abroad
  question. Nationality and immigration status are never stored.
- Phone numbers, CNICs and IBANs are stored in exactly the form `mm_core` reads back; the
  database CHECKs and `mm_core` share `contracts/identity_vectors.json`. Never infer gender from
  a CNIC, and mask CNICs by default.
- An amount read from words or free text comes from `parseAmount` (`mm_core`), never from a
  model's text alone: it returns `ambiguous` rather than guess, and is read back in words
  (`formatAmountWords`) before it is saved. Its words are `contracts/amount_lexicon.json`, and
  `contracts/amount_vectors.json`, written by hand, is the contract every port runs.

## Database

- A change is a new migration in `supabase/migrations/`, never an edit to an applied one. The
  migrations after the squawk baseline in `.squawk.toml` are linted by `make lint`.
- Locks are taken in one global order: account, then portfolio, then lease, then other rows.
  Client writes lock their portfolios first through `app.lock_my_portfolio_ids`.
- Authorisation lives in Postgres: row-level security on every table, explicit column grants,
  and `SECURITY DEFINER` write RPCs that check the caller's role. The 23 such RPCs are pinned in
  `supabase/tests/database/01_schema_security.test.sql`; a new one updates that list and
  `docs/architecture/permissions.md`.
- Every migration comes with pgTAP tests, a concurrency scenario when rows can be written in
  parallel, and an upgrade test in `tool/db/upgrade/` when it changes existing rows.
- The hosted project is changed only through the process in
  `docs/operations.md`, "After every migration".

## Addresses

- The website's and the web app's production origins, and the earlier addresses that send people
  on to them, are written once: [`contracts/origins.json`](../../contracts/origins.json) (decision
  D-20). Code reads it (the website's defaults, the deck, the workflows' `APP_URL` and their
  checks that the addresses answer, the page the web app's earlier address answers with). Two
  files spell the addresses themselves and are checked against it: the Android manifest's App Link
  hosts (`tool/android/check_manifest.py`) and `website/vercel.json`'s redirect (the website's
  unit tests). Docs name the origins through the `site-origin` and `app-origin` facts where they
  can, and `make docs-check` (C17) checks every other address: a host on the domain must be an
  origin or alias, an earlier address appears only in the files `LEGACY_PATHS` lists (in
  `tool/docs/fact_registry.py`), no workflow names an origin, and the only mailbox on the domain
  that a file may name is one the owner made: `NAMED_MAILBOXES` in the same file, today the
  company's `hello@mmakaan.app`, which the website gives as its contact address (`contactEmail` in
  `website/src/config/site.ts`). The pre-commit hook runs C17 for code too (`C17_CODE`).
- A test that needs an address uses `example.pk` or `example.org`, or reads the production ones
  from the file; none writes one.

## Secrets and privacy

- Clients take the publishable key only; `AppConfig` refuses an `sb_secret_` key or a
  service-role JWT. Service keys live in Edge Function secrets and GitHub secrets.
- gitleaks scans the whole history in CI (`security.yml`, `.gitleaks.toml`).
- No real names, CNICs, phone numbers or documents in code, tests, fixtures, logs or
  screenshots.

## Workflows and actions

- A reusable workflow or an action in this repository is referenced with GitHub's
  self-repository syntax, `uses: $/.github/workflows/deploy.yml`: never `./…`, and never with an
  `@ref`. The reasons differ by kind. For a step-level action, `$/` resolves to the repository
  at the running commit, while `./` resolves against the runner's workspace, which an earlier
  step can replace. For a reusable workflow, both forms take the called file from the caller's
  own commit, and `$/` is used because it is GitHub's recommended form, because zizmor's
  `self-repository` audit flags `./`, and because a fully-pinned actions policy counts `$/` as
  pinned and `./` not. (`$/` does not exist on GitHub Enterprise Server, which this repository
  does not use.)
- actionlint 1.7.12 refuses `$/`, and then stops checking the call against the called workflow.
  `.github/actionlint.yaml` ignores exactly that message, for a `$/` call without an `@ref`, and
  `tool/github/check_workflow_calls.py` (`make lint`, the pre-commit hook) checks instead: it
  refuses `./` in any workflow or `action.yml`, and for each job-level `$/` call it requires a
  workflow directly in `.github/workflows` that declares `on.workflow_call`, declared `with:`
  and `secrets:` keys (or `secrets: inherit`), every required input without a default and every
  required secret passed, literal values of the declared type, and no `@ref`. Its canary test
  fails once the pinned actionlint accepts `$/`; then the ignore goes and the check keeps only
  what actionlint does not cover. actionlint also refuses a step-level `$/` action (its
  `[action]` rule, not ignored): the repository has no action of its own today, and the first
  one needs that ignore and the check of its inputs added together.
- Every job that runs `supabase start` (or `supabase db start`) first runs the step "Reserve the
  local stack's host ports", in one spelling, before any step that connects out:

  ```yaml
  - name: Reserve the local stack's host ports
    run: |
      reserved="$(cat /proc/sys/net/ipv4/ip_local_reserved_ports)"
      echo "${reserved:+$reserved,}54320-54329" | sudo tee /proc/sys/net/ipv4/ip_local_reserved_ports
  ```

  Linux gives an outgoing connection a local port from `net.ipv4.ip_local_port_range` (32768 to
  60999 by default), and while that socket lives, or lingers in `TIME_WAIT`, a bind of the
  wildcard address to the same port fails with `EADDRINUSE`. The stack's host ports lie in that
  range, and a job binds them straight after pulling the images over many connections: CI run
  43740334888 (UAT, 15 November 2026) stopped so on `0.0.0.0:54322`. A port in
  `net.ipv4.ip_local_reserved_ports` is never given out automatically, while an explicit bind of
  it works as before; a reservation does not free a port a socket already holds, hence the first
  step. The range is literal, so the step needs no checkout and runs first; it is the Supabase
  CLI's whole default block (shadow database 54320 to pooler 54329), so a service turned on
  later is covered. The write keeps any ports already reserved, and `tee` fails the step when
  the kernel refuses it, where `sysctl -w` prints "ignoring" and exits 0. The backup's restore
  check is allowed to fail, so there the step has `continue-on-error` and the stack starts only
  when it succeeded (`steps.reserve.outcome == 'success'`). `tool/github/check_stack_ports.py`
  (`make lint`, the pre-commit hook) requires all of this, and that the range covers every port
  `supabase/config.toml` names inside 32768 to 60999 (a port below it is never given out).

- zizmor findings fail the gate, at every severity, unless an inline ignore suppresses them.
  `make lint` (so the Repository hygiene job) runs the zizmor that `tool/requirements-lint.txt`
  installs offline, with `--strict-collection`, on the whole repository; the Security workflow's
  "Workflow security (zizmor)" job runs the same version with its online audits, uploads the
  results to code scanning, then fails on any finding that is not suppressed. `make docs-check`
  (its `zizmor-pin` check) keeps the two versions equal, and `tool/requirements-lint.in` equal
  to the lockfile. A finding is fixed; an exception is an inline `# zizmor: ignore[<audit>]`
  with its reason, agreed in review.

## Design

- UI code takes colours, type, spacing, radii and motion from tokens (`MmSpace`, `MmRadius`,
  `MmMotion`, the theme). `make design-lint` fails otherwise; a reviewed exception carries
  `// design-lint: allow <reason>`.
- Components come from `packages/mm_ui`; the visual rules are `DESIGN.md`, the code conventions
  `packages/mm_ui/COMPONENTS.md`.
- WCAG 2.2 AA: 48 dp targets, 4.5:1 text contrast, labelled controls, 200% text. The test
  harnesses check each in every variant.

- Review every changed image before committing it, and say in the pull request which goldens

**Generated facts in the docs.** A fact the docs repeat (the commit scopes, the coverage gates,
the test counts, the website's checks) sits between markers that name its source, and
`make docs` rewrites the text between them:

- Never edit between the markers: change the source and run `make docs`, which also runs
  Prettier on those files. `make docs-check` (CI and the pre-commit hook) fails on a stale fact.
- An inline marker never begins a line, or CommonMark reads the line as raw HTML; a block
  marker stands alone on its line, with a blank line on each side of the body. No marker goes in
  fenced code, `CHANGELOG.md`, `llms.txt` or `.planning/`.
- To show a fact in a new place, put an empty pair of markers there
  (`<!-- docs:KEY --><!-- /docs:KEY -->`), add the file to the fact's `targets` in
  `tool/docs/fact_registry.py` and run `make docs`. A new fact goes in the same file, with its
  parser in `tool/docs/fact_sources.py` and tests.
- Copies the tool checks but does not write are fixed by hand: versions named in prose (in
  `llms.txt` too), workflow pins, the CI jobs table, every `make` reference, this table, the
  README's release line, which release-please writes, the ranges of decisions and proposals, and
  the counts of golden variants, TLA+ models and pgTAP tests (in the deck's slides too).
  `python3 tool/docs/sync_facts.py --list` lists them all.

A broken marker is reported with its rule (M1 to M16, listed in `tool/docs/fact_markers.py`)
and what to change; a source whose shape changed is reported with the parser to update.

## Dependencies

Adding, removing or upgrading a direct dependency, or bundling a font or icon set, updates
`THIRD_PARTY_NOTICES.md` with its version and licence. Copyleft code (GPL, LGPL, AGPL, MPL)
needs the owner's agreement before it ships. Every GitHub Action is pinned to a commit SHA.

Dependabot pull requests (`.github/dependabot.yml`) change only the manifest and lockfile, so a
bump is not done until the same branch updates `THIRD_PARTY_NOTICES.md` and any README or
comment naming the old version, and rebuilds generated files that depend on it (`make icons`
after lucide-static). A bump of zizmor in `tool/requirements-lint.txt` also changes its pin in
`tool/requirements-lint.in` and `version:` of zizmor-action in `security.yml` (`make docs-check`
fails until all three agree). A lockfile is written with the npm in `packageManager`, which is the npm
that the Node in `.nvmrc` bundles. When a bump moves a pinned override with it (the website's
`playwright-core` follows `@playwright/test`), the override changes in the same commit.
