# AGENTS.md

Maalik-e-Makaan (مالکِ مکان) is tenant and property management for Pakistani landlords, in
English and Urdu: a Flutter app on a Supabase backend, an Astro website, and formal models of
the money and concurrency code. This file is the entry point for coding agents. It is short on
purpose: read the file for the area you are changing, not everything.

## Commands

Every check is a `make` target, and CI runs the same targets. `make help` lists them all;
[`docs/agents/commands.md`](docs/agents/commands.md) maps each to its area, prerequisites and CI job.

```sh
make bootstrap                           # pub, npm (installs the git hooks), deno, Python tools in .venv
make format-check-repo lint docs-check   # docs, shell, Python, workflows, migrations, Android manifest, design lint, Unicode and Urdu guards, repeated facts
make format-check analyze                # adds Dart and Deno formatting and every analyzer
make test                                # tooling, mm_core, mm_ui, gallery, app, database, Edge Functions
make test-uat                            # browser UAT on a local Supabase stack (docs/uat.md)
```

Toolchain on the path: `export PATH=/opt/flutter/bin:$PWD/.venv/bin:$PATH` (see
[`.planning/STATE.md`](.planning/STATE.md), Environment Notes, for the local PostgreSQL 16 on
port 54329 and what this container cannot reach).

## Rules that apply everywhere

- **Commits**: Conventional Commits with a scope from `commitlint.config.mjs`: <!-- docs:commit-scopes from commitlint.config.mjs scope-enum; generated by make docs, do not edit -->`app`, `core`,
  `ui`, `db`, `functions`, `web`, `ci`, `deps`, `deps-dev`, `docs`, `formal`, `planning`,
  `release`, `repo`, `security`, `test`<!-- /docs:commit-scopes -->. Body lines at most 100 characters. Pull requests are
  squash-merged, so the title follows the same rule, and with the `(#123)` GitHub adds it
  stays within the 100-character header.
- **British English** in prose, comments and UI text (`licence`, `colour`, `organisation`);
  identifiers follow their framework (`MmColorModes`, `MmLicenses`). Every user-facing string
  exists in English and Urdu.
- **Plain Urdu**: the everyday words an ordinary landlord or tenant reads easily, in Urdu script
  (an English word people say is written in it: `سیکیورٹی`). `make lint` runs
  `tool/check_urdu_words.py`, which refuses the words `contracts/urdu_glossary.json` avoids.
- **No secrets, no real people.** Clients take only the publishable key (`AppConfig` refuses a
  secret key). No real names, CNICs, phone numbers or documents in code, tests, logs or
  screenshots.
- **Money is whole paisa in integers** (`Money` in `mm_core`), `numeric(14,2)` in SQL. Never a
  floating-point type. Financial rows are voided, never deleted.
- **Lock order**: account, then portfolio, then lease, then other rows. Every write path keeps it.
- **Migrations**: always a new file, never an edit to one in `supabase/migrations/`. The hosted
  project (`aaifamxzzjspohwksxyr`) is changed only by the process in
  [`docs/operations.md`](docs/operations.md#after-every-migration).
- **Design lint**: UI code takes colours, type, spacing, radii and motion from tokens and uses
  directional geometry (`make design-lint`).
- **Unicode guard**: no bidi controls, invisible or control characters in tracked files
  (`tool/check_unicode.py`, `contracts/clean_text.json`).
- **Goldens**: re-record with `make goldens` only on Linux, and look at every changed image
  before committing it.
- **Generated files** are rebuilt, not edited: see
  [`docs/agents/conventions.md`](docs/agents/conventions.md#generated-files).

The full list, with the reasons, is [`docs/agents/conventions.md`](docs/agents/conventions.md);
how to do common tasks is [`docs/agents/workflows.md`](docs/agents/workflows.md).

## How to work here

- **You own the project.** Work as its engineer and owner: take a change all the way through
  (code, tests, docs, CI, review, merge), report what you find on the way, and leave each area
  better than you found it. Grow it with the free tiers and startup credits the owner has (PostHog,
  Intercom, Customer.io, Higgsfield and others), inside the decisions in
  [`.planning/PROJECT.md`](.planning/PROJECT.md): analytics, for example, are privacy-first (D-18).
- **No shortcuts.** No hand-waving, no stub presented as finished, no skipped or loosened test,
  no claim you have not checked. Spend the time, tool calls and review rounds the work needs:
  quality comes before speed.
- **Use the tools you have.** Before a task, look at the skills, MCP servers and tools available
  and use the ones that fit: among them `release-readiness-audit`, `cli-tool-qa`,
  `design-systems-engineering`, `project-documentation`, `gsd`, `code-quality-standards`,
  `seo-audit`, `brand-review`, `code-review` and `llm-context-modular-docs`, browser and computer
  use, and Context7 or the official documentation for any library or API.
- **Ask the owner** when a decision is theirs (product, pricing, legal, privacy, and anything
  that reaches outside the repository: a release, a change to the hosted project, a write to an
  external service), or when you are blocked. Otherwise decide, and record the decision.
- **Keep the documentation current.** A pull request updates every document its change makes
  wrong: the READMEs, the `AGENTS.md` files, `docs/`, `.planning/` and `llms.txt`.
  `CHANGELOG.md` is written by release-please from the squash commits, so a commit message says
  what changed for the person reading the changelog. A fact that appears in several places is
  generated from its source by `make docs` (never edit between `<!-- docs:… -->` markers), and
  `make docs-check` fails CI when a copy drifts. A new repeated fact goes into
  `tool/docs/fact_registry.py`, not into another hand-made copy.

## Quality bar

The owner's definition of done for every area. [`docs/agents/quality-bar.md`](docs/agents/quality-bar.md)
says what each means here, the gates in force today and what is still to reach.

- **Frontend** (the app, `mm_ui` and the website): high-quality, clean, intuitive, interactive,
  consistent, fast and responsive to touch, beautiful and tasteful, accessible to WCAG 2.2 AA,
  optimised for search engines and AI answer engines, mobile-first, responsive and reliable. Every
  screen and page is built from the shared design system (tokens, type, themes, presets, motion,
  states and components), not from one-off styles.
- **Testing**: 100% coverage is the floor. The tests also cover every relevant case: edge cases,
  failure paths, concurrency, performance and stress, security and input sanitisation, smoke
  tests and fuzzing, at the unit, integration and end-to-end levels.
- **CI/CD**: gates for code quality and validation, security, coverage, maintenance (Dependabot)
  and the release lifecycle, on every pull request or on a schedule.
- **API and database**: every implicit state machine is found, written down and enforced. The
  whole stack is hardened: type safety, rate limits, caching, indexes, roles and row-level
  security, timing-safe comparison of secrets, and search-engine readiness. The aim is a
  complete, fast and secure production system.
- **Formal verification**: every money path, every concurrency protocol and every state machine
  they pass through has a model or a proof that CI checks, tied to the code by contract vectors,
  replays and mutants that must fail. Properties have names, assumptions name the guard that makes
  them true, and a change to modelled code updates its track in the same pull request. A prose
  argument is not evidence.
- **Agentification** (agents that build the repository, and agents in the product): in the
  repository, layered context, rules a machine checks, the same gates for every author, evidence
  instead of claims, a review pass before merge, stated limits on what an agent does alone, and
  commits that name their agent. In the product, agents get the least they need: read-only by
  construction, writes only as drafts within a mandate a person grants and can revoke, with
  consent, audit, rate limits, deterministic checks around every model output, and evaluation sets
  with a held-out part.
